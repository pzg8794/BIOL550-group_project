Mouse RNA-Seq — Alignment Validation & Local Reproducible Analysis

BIOL550 — Weekly Report — Mar 19, 2026

What I accomplished since the previous report

This week, the mouse project moved from QC remediation into alignment validation. I reviewed the first full canonical STAR run across all 26 paired-end SRRs in PRJNA1017789/GSE243308 (using the cleaned fastp inputs) and validated the run outcomes at the summary-metrics level.

To make the validation reproducible and easy to extend, I set up a local notebook that parses all 26 Log.final.out files and all 26 ReadsPerGene.out.tab files, joins those alignment metrics to run metadata and sequencing platform labels (NovaSeq 6000 vs NovaSeq X) plus the earlier GC-WARN/GC-PASS flags, and exports the reverse-stranded count matrix (column 4) as the handoff artifact for DESeq2.

The alignment results support moving forward with the complete dataset: median unique mapping is ~94%, no sample collapses into a failed-alignment regime, and platform/GC differences look like structured metadata to carry forward rather than reasons to exclude a subset.

Methods used

Canonical alignment input:
- cleaned FASTQs: full fastp rerun (all 26 SRRs)
- reference: GRCm39 + matching Ensembl GTF
  (Mus_musculus.GRCm39.dna.primary_assembly.fa,
   Mus_musculus.GRCm39.115.gtf)
- mapper: STAR (sjdbOverhang 150, GeneCounts)

STAR index (once):
STAR --runMode genomeGenerate --runThreadN 8 \
  --genomeDir star_index_sjdb150 \
  --genomeFastaFiles Mus_musculus.GRCm39.dna.primary_assembly.fa \
  --sjdbGTFfile Mus_musculus.GRCm39.115.gtf \
  --sjdbOverhang 150

STAR alignment (per sample):
STAR --runThreadN 8 --genomeDir star_index_sjdb150 \
  --readFilesIn SRR_1.trim.fastq.gz SRR_2.trim.fastq.gz \
  --readFilesCommand zcat \
  --outSAMtype BAM SortedByCoordinate \
  --quantMode GeneCounts

Local validation workflow

  • Parsed all Log.final.out files for alignment metrics.
  • Parsed ReadsPerGene.out.tab (special rows + gene counts).
  • Joined metrics to metadata: platform + GC-WARN/GC-PASS.
  • Exported reverse-stranded counts (column 4) for DESeq2.

Strandedness was treated as reverse for the DESeq2 handoff (column 4), consistent with earlier strandedness checks/class discussion.

NovaSeq X aligns somewhat better than NovaSeq 6000, but both remain usable. Assignment burden (N_noFeature, N_ambiguous) stays comparable, supporting a batch-style platform effect rather than failure.

GC-WARN vs GC-PASS at alignment

GC-WARN aligns slightly worse than GC-PASS, but does not form a collapsed outlier group; keep the GC label as metadata in DE, not as a filter.

Problems encountered

Main issues were analytical rather than blocking: the platform split remains visible at alignment, so platform should stay explicit in downstream DE modeling and interpretation. The GC-WARN label also remains meaningful (modestly weaker unique mapping / higher multi-mapping), so it should carry forward as a tracking label rather than a filter.

Workflow-control note: shared trimmed FASTQs were confirmed non-equivalent to the canonical private fastp run, so the canonical private input root remains the correct alignment source. Local BAM/BAI transfer is large, so the notebook validates first from STAR summary outputs (Log.final.out + ReadsPerGene.out.tab) without waiting for full BAM copies.
