Mouse RNA-Seq — Alignment Validation & Local Reproducible Analysis

BIOL550 — Weekly Report — Mar 19, 2026

Accomplishments since the previous report

This week the mouse project moved from QC remediation into alignment validation. I analyzed the first full canonical STAR run across all 26 paired-end SRRs in PRJNA1017789 / GSE243308, set up a local reproducible environment, and built a notebook-based alignment evidence package. The local workflow parsed all 26 Log.final.out and ReadsPerGene.out.tab files, joined those metrics to sample metadata, sequencing-platform labels, and the earlier GC-WARN / GC-PASS classification, and exported a reverse-stranded count handoff matrix. Across all samples the median unique-mapping rate is approximately 94%; no sample collapses into a failed-alignment regime. The remaining platform and GC differences look like metadata to carry forward rather than reasons to halt. This report marks the transition from cleanup validation into count-level analysis and DE preparation.

Methods

Canonical alignment input:
- cleaned FASTQs from the full fastp rerun
- reference = GRCm39 + matching Ensembl GTF
- mapper = STAR

STAR index:
STAR \
  --runThreadN 8 \
  --runMode genomeGenerate \
  --genomeDir star_index_sjdb150 \
  --genomeFastaFiles Mus_musculus.GRCm39.dna.primary_assembly.fa \
  --sjdbGTFfile Mus_musculus.GRCm39.115.gtf \
  --sjdbOverhang 150

STAR alignment (per sample):
STAR \
  --runThreadN 8 \
  --genomeDir star_index_sjdb150 \
  --readFilesIn SRR_1.trim.fastq.gz SRR_2.trim.fastq.gz \
  --readFilesCommand zcat \
  --outSAMtype BAM SortedByCoordinate \
  --quantMode GeneCounts

Local validation workflow:

  • Copy canonical STAR summary outputs locally.
  • Parse all Log.final.out files (alignment stats).
  • Parse all ReadsPerGene.out.tab files (gene counts).
  • Join metrics with sample metadata, platform, and GC status.
  • Export reverse-stranded count matrix for DESeq2.

This setup enabled independent validation of the server-side run in a reproducible notebook without repeated server-side reanalysis. The GC-content split was shown in recent class sessions to correlate with sequencing instrument rather than a biological subgroup, making platform comparison at alignment the key next check — confirmed here.

Key figures

Per-sample unique mapping — all 26 SRRs (canonical STAR run)

No sample collapses into a failed-alignment regime. The full set clusters in a high-mapping range around 94%, confirming the data are technically usable for downstream expression analysis. Lower-performing samples remain worth tracking but fall well within an acceptable range.

Platform split at alignment

NovaSeq X aligns somewhat better (left) and shows comparable assignment burden (right). The platform split is real but does not indicate a failed platform — it corroborates the class-discussion finding that the GC-content shift tracks instrument structure, a batch effect to model downstream rather than a reason to exclude samples.

GC-WARN vs GC-PASS at alignment

GC-WARN samples align somewhat worse but remain high overall and do not form a collapsed outlier group. Because GC-WARN samples cluster strongly with the older platform, the GC bimodality is best explained as a platform-linked shift rather than a trimming failure. Both subsets proceed.

Limitations

  • Platform split persists at alignment — platform must remain explicit metadata in DE modeling.
  • GC-WARN subset shows modestly lower unique mapping and higher multi-mapping — carry the label forward into count-level and DE notebooks.
  • Local BAM / BAI transfer from the server is slow and large; the validation notebook was intentionally designed to proceed from STAR summary outputs first.

None of these block the project. The alignment results support proceeding with the full dataset.
